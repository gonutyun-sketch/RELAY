# POWER 70 / 30 판정과 벽의 힌트 종이

POWER만 변경한다. 전압계의 VOLTAGE가 70 V, CURRENT가 30 A일 때 MAIN을 켤 수 있다. COOLING과 다른 퍼즐은 바꾸지 않는다.

종이의 내용은 다음 두 숫자뿐이다. 제목, 단위, 조작 설명, 추가 힌트를 종이에 쓰지 않는다.

```text
70
30
```

파일은 프로젝트 밖에 준비했다. 아래 코드·씬·Inspector 적용은 사용자가 직접 진행한다.

## 1. 코드 세 개 적용

Play 정지 → 현재 씬 저장.

| 제공 파일 | 적용 방법 |
|---|---|
| Code/PowerModule.cs | Assets/RELAY/Scripts/PowerModule.cs를 열고 내용 전체 교체 |
| Code/PowerCalibrationRule.cs | Assets/RELAY/Scripts에 새 파일 추가 |
| Code/PowerHintInspect.cs | Assets/RELAY/Scripts에 새 파일 추가 |

기존 PowerModule.cs 파일과 `.meta`를 삭제하거나 컴포넌트를 제거하지 않는다. Ctrl+A로 내용만 교체하면 기존 AUX / Voltage Dial / Balance Dial / MAIN 연결을 유지할 수 있다. 파일 이름 뒤에 `1`이나 `복사본`을 붙이지 않는다.

PowerCalibrationRule은 계산용 클래스이므로 Add Component로 붙이지 않는다. PowerHintInspect만 뒤에서 벽 종이 오브젝트에 붙인다.

세 파일을 모두 저장하고 컴파일이 끝나길 기다린다.

## 2. POWER 조건 확인

기존 PowerModule의 70~80V / 40A 이하 설정을 제거하고 70V / 30A를 고정 조건으로 사용한다. 허용 오차나 반올림으로 통과시키지 않는다.

Inspector에서 기존 Min Voltage / Max Voltage / Max Current 칸이 사라지는 것이 정상이다. AUX Power / Voltage Dial / Balance Dial / Main Lever 연결은 유지한다.

기존 다이얼 설정도 유지한다.

| 컨트롤 | Min | Max | Step | Initial Value |
|---|---:|---:|---:|---:|
| VOLTAGE_Dial | 0 | 100 | 5 | 50 |
| BALANCE_Dial | 0 | 100 | 10 | 0 |

여기서 목표는 **다이얼에 적힌 값이 아니라 전압계에 표시되는 VOLTAGE / CURRENT 값**이다. 부하 분배를 조절하면 전압과 전류가 함께 변하는 기존 계산을 유지했다.

MAIN을 켠 뒤 값이 틀어지거나 AUX를 끄면 MAIN이 해제된다. 값을 복구해도 자동으로 다시 켜지지 않는다.

## 3. 벽에 힌트 종이 붙이기

현재 저장된 씬에서 Environment의 Transform은 Position/Rotation 0, Scale 1이며, 뒤쪽 벽은 Z=6 근처다. 제작한 LAB_Wall_Back의 해당 콘크리트 표면은 Z 약 5.744다. 아래 값은 그 벽 앞에 종이를 붙이는 시작 위치다. Unity에서 시각적인 겹침은 마지막 확인 단계에서 확인한다.

Hierarchy에서 **Environment 우클릭 → Create Empty**. 이름 `POWER_Hint`.

POWER_Hint Transform:

| 항목 | X | Y | Z |
|---|---:|---:|---:|
| Local Position | 3.2 | 1.65 | 5.74 |
| Local Rotation | 0 | 0 | -3 |
| Local Scale | 1 | 1 | 1 |

POWER_Hint는 **Environment의 직접 자식**으로 둔다. 크기가 늘어난 Wall_Back Cube나 Panel_POWER의 자식으로 넣지 않는다.

POWER_Hint에 **Box Collider** 추가:

- Center `(0,0,0.004)`
- Size `(0.30,0.42,0.01)`
- Is Trigger OFF
- Layer Default
- Rigidbody는 추가하지 않는다.

이 Collider는 종이를 조준하고 클릭할 때 사용한다. 벽과 가까이 붙어 있도록 깊이는 1cm만 둔다.

### WorldPaper — 실제 벽에 보이는 종이

POWER_Hint 밑에 UI → Canvas를 만들고 `WorldPaper`로 이름 변경.

Canvas:

- Render Mode: World Space
- Event Camera: Player > Main Camera
- Graphic Raycaster는 필요 없으므로 제거 가능

Rect Transform:

| 항목 | 값 |
|---|---|
| Width / Height | 300 / 420 |
| Pivot | 0.5 / 0.5 |
| Local Position | 0, 0, 0 |
| Local Rotation | 0, 0, 0 |
| Local Scale | 0.001, 0.001, 0.001 |

WorldPaper 우클릭 → UI → Image → 이름 `Paper`.

- Rect Transform: Anchor Min `(0,0)`, Max `(1,1)`.
- Left / Right / Top / Bottom 모두 0.
- Rotation 0, Scale 1.
- Image: Source Image None, Material None, Color `DDD5BD`, Alpha 255.
- Raycast Target OFF.

Paper 우클릭 → UI → Text - TextMeshPro → 이름 `Numbers`.

- 양방향 Stretch, Left / Right / Top / Bottom 모두 20.
- Rotation 0, Scale 1.
- Font: 기존 LiberationSans SDF.
- Font Size 76, Auto Size OFF, Font Style Normal.
- Color `292824`, Alpha 255.
- Alignment: 가로 중앙 / 세로 중앙.
- Line Spacing 15, Margins 모두 0.
- Raycast Target OFF.
- Text Input: `70` 입력 → 실제 Enter → `30` 입력. 문자 `\n`을 타이핑하지 않는다.

현재 구조:

```text
Environment
└─ POWER_Hint                   ← Box Collider
   └─ WorldPaper                ← World Space Canvas
      └─ Paper                  ← Image
         └─ Numbers             ← 70과 30만
```

종이는 전원이 없을 때도 읽을 수 있다. MAIN을 켜기 위한 힌트이므로 전원 조건에 연결하지 않는다.

## 4. 클릭했을 때 확대되는 종이 UI

기존 화면용 **Canvas** 아래에 만든다. WorldPaper, TerminalScreen, PauseMenu 밑에 만들지 않는다. 기존 Canvas는 Screen Space - Overlay와 Canvas Scaler 1920×1080 / Scale With Screen Size / Match 0.5를 유지한다.

### PowerHintView

기존 Canvas 우클릭 → UI → Image → 이름 `PowerHintView`. Canvas의 마지막 자식으로 둔다. **Canvas Group** 컴포넌트 추가.

Rect Transform:

- Anchor Min `(0,0)`, Max `(1,1)`.
- Left / Right / Top / Bottom 모두 0.
- Pivot `(0.5,0.5)`, Rotation 0, Scale 1.

Image:

- Source Image None, Material None.
- Color 검정, Alpha 165/255.
- Raycast Target ON.

Canvas Group:

- Alpha 1 — 편집 중 확인용. 실행 시 코드가 자동으로 숨긴다.
- Interactable OFF.
- Blocks Raycasts ON.
- Ignore Parent Groups OFF.

### PaperPivot

PowerHintView 우클릭 → **Create Empty** → 이름 `PaperPivot`. Canvas 안에 만드는 UI용 빈 오브젝트다. Rect Transform이 있어야 한다.

- Anchor Min/Max `(0.5,0.5)`.
- Pivot `(0.5,0.5)`.
- Pos X/Y `0 / 0`.
- Width 420, Height 588.
- Rotation `(0,0,-2)`, Scale `(1,1,1)`.

PaperPivot 우클릭 → UI → Image → 이름 `Paper`.

- 양방향 Stretch, 네 방향 여백 모두 0.
- Rotation 0, Scale 1.
- Source Image None, Material None.
- Color `DDD5BD`, Alpha 255, Raycast Target OFF.

Paper 밑에 UI → Text - TextMeshPro → 이름 `Numbers`.

- 양방향 Stretch, 네 방향 여백 모두 32.
- Font LiberationSans SDF, Size 120, Auto Size OFF, Normal.
- Color `292824`, Alpha 255.
- 가로 중앙 / 세로 중앙 정렬, Line Spacing 15, Margins 0.
- Rotation 0, Scale 1, Raycast Target OFF.
- Text Input은 벽 종이와 똑같이 `70`과 `30`을 두 줄로 입력한다.

```text
Canvas
├─ ...                          ← 기존 UI 유지
└─ PowerHintView                ← Image + CanvasGroup
   └─ PaperPivot                ← UI 빈 오브젝트, 움직일 부분
      └─ Paper                  ← Image
         └─ Numbers             ← 70과 30만
```

종이 안에 다른 텍스트나 버튼을 만들지 않는다. 편집 중에는 새 UI 오브젝트들의 Active를 ON으로 둔다. Play하면 자동으로 숨겨지고 종이를 클릭할 때만 나타난다.

## 5. 스크립트 연결

Hierarchy에서 **Environment > POWER_Hint** 선택 → Add Component → **Power Hint Inspect**.

스크립트는 WorldPaper나 PaperPivot이 아니라, Collider가 있는 POWER_Hint에 한 번만 붙인다.

| 항목 | 연결 |
|---|---|
| Display Name | PAPER |
| Motor | 기존 Player의 First Person Motor |
| View Group | 기존 Canvas > PowerHintView의 Canvas Group |
| Paper Pivot | PowerHintView > PaperPivot의 Rect Transform |
| Drag Sensitivity | 0.08 |

코드 연결과 오브젝트 생성까지 끝났으면 씬 저장.

## 6. 조작과 확인

1. Play 후 시작 화면·프롤로그가 기존처럼 나온다. 종이 확대 화면이 처음부터 떠 있으면 안 된다.
2. 벽 종이를 2.5m 이내에서 조준하고 왼쪽 클릭한다. 커서가 풀린 상태였다면 첫 클릭은 기존처럼 커서 잠금만 하고, 다음 클릭이 종이를 연다.
3. 확대된 종이에 `70`, `30`만 보인다. 이때 WASD와 마우스 시점 회전은 멈춰야 한다.
4. 종이를 연 클릭을 한 번 놓은 다음 **왼쪽 버튼을 누른 채 드래그**하면 종이가 조금 움직이고 기울어진다. 각도에 제한을 두어 종이 뒷면으로 넘어가지 않는다.
5. **휠**로 조금 확대/축소할 수 있다. **오른쪽 클릭 또는 Esc**로 닫는다. Esc가 설정창까지 동시에 열면 안 된다.
6. 닫으면 플레이어 조작이 돌아온다. Alt+Tab으로 창 밖으로 나가면 종이를 닫고 커서를 풀며, 돌아온 뒤 첫 클릭은 커서 잠금만 한다.
7. POWER 계기판이 70V / 30A일 때만 MAIN이 켜지는지 확인한다. 다른 값을 맞추면 기존 빨간 조준선 거절 반응이 나와야 한다.
8. MAIN이 켜진 뒤 다이얼을 한 칸 움직이면 MAIN이 해제되는지 확인한다. AUX OFF도 확인한다.
9. 종이 가장자리가 벽에 묻히거나 떠 있지 않은지 옆에서 본다. 위 배치는 기존 LAB_Wall_Back 원본 치수를 기준으로 표면에서 약 4mm 앞이다. 사용자가 벽 모델 위치를 바꿨다면 그 실제 표면에 맞춰 종이 Z만 조정한다.
10. 1920×1080과 1280×720에서 확대 종이와 숫자가 잘리지 않는지 확인한다. Console에 빨간 오류가 없어야 한다.

## 개발 확인용 — 종이에는 적지 않음

현재 연동 계산에서 **VOLTAGE 다이얼 75, LOAD BALANCE 50**이면 전압계에 **70V / 30A**가 나온다. 사용자가 요구한 정답은 계기판 기준 70 / 30이다.

코드와 다이얼 간격을 유지한 채 실제 도달 가능한 231개 조합을 검사했다. 그중 이 조합 하나만 통과한다. 게이지의 소수 첫째 자리 표시가 정답처럼 보이지만 실제로는 다른 값인 조합도 현재 간격에서는 없다.

## 검증

- 새 POWER 규칙 485개 검사 통과: 현재 다이얼 전체 조합, 정확한 수치, 기존 범위 안의 오답, 목표 근처 오답, 잘못된 수치.
- 현재 프로젝트와 새 파일을 합친 40개 C# 파일을 Unity 6000.3.9f1 라이브러리로 외부 컴파일: Player / Editor 모두 오류 0개. 기존 PauseSettings의 미사용 필드 경고는 그대로다.
- 검사 전후 프로젝트 스크립트와 씬 해시 동일. Unity 화면/씬/Inspector를 직접 조작하거나 프로젝트 소스를 수정하지 않았다.
- 종이의 실제 클릭·드래그·닫기와 화면 배치는 Unity에서 아직 플레이 검증하지 않았다. 위 수동 적용 후 확인한다.
